# Bug Fixes - Session Notes

## Bugs Corrigidos (2025-11-29)

### ✅ 1. Certificado A1 - Senha Incorreta Sempre Rejeitada

**Problema**: O sistema sempre rejeitava a senha do certificado A1, mesmo quando correta.

**Causa**: O `node-forge` lança diferentes tipos de exceções dependendo do erro ao fazer parse do PKCS#12, mas o código só verificava a mensagem "Invalid password" exata.

**Solução**: Melhorado o `catch` em `certificate.service.ts` para detectar múltiplos tipos de erros relacionados a senha:
- "Invalid password"
- "password" (genérico)
- "MAC" (Msg Authentication Code)
- "decrypt" (descriptografia falhou)
- "Authentication"
- Erros genéricos do forge

**Arquivo**: `/src/services/certificate.service.ts` (linhas 140-156)

---

### ✅ 2. Botão "Novo Atendimento" Não Funcionava

**Problema**: Clicar em "Novo Atendimento" no menu quick create do Header não abria o modal.

**Causa**: O `ServiceFormModal` não estava registrado no `GlobalModals.tsx`, apesar do ModalContext ter o tipo 'service'.

**Solução**: Adicionado `ServiceFormModal` ao `GlobalModals.tsx`:
- Import do componente
- Renderização condicional quando `activeModal === 'service'`

**Arquivos**:
- `/src/components/GlobalModals.tsx` (adicionado ServiceFormModal)
- `/src/components/Header.tsx` (botão já estava correto - linha 257)

---

### ⚠️ 3. Jus.br OAuth - Não Conecta

**Problema**: Botão "Conectar com Jus.br" não funciona conforme esperado.

**Causa Root**: **Endpoints OAuth placeholders** - Os endpoints do CNJ SSO em `jusbr-oauth.service.ts` são URLs de exemplo, não reais:
```typescript
authorizationEndpoint: 'https://sso.cnj.jus.br/auth'  // ❌ Placeholder
tokenEndpoint: 'https://sso.cnj.jus.br/token'        // ❌ Placeholder
```

**Status**: **LIMITAÇÃO CONHECIDA** - Não pode ser corrigido sem:

2. Endpoints oficiais do PJe/CNJ SSO
3. `clientId` real registrado
